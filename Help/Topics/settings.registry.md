# Installing machines and effects

What this installation has, and how a box arrives or leaves.

Two folders and only one of them is yours. Beside the program is what ships: a source
to take a machine from, never written to. Under the application folder is what this
installation actually has, and that one alone decides what is on the rack, what a
song can be given, and what has a panel.

## Adding and removing

**Add** takes a shipped box and registers it here. **Remove** unregisters one, and
that is not losing it: the shipped copy stays where it was and can be taken again.
**Import** reads a zip somebody handed you.

What is recorded is what has been *offered*, not what is present. So a machine
written after your folder was made still arrives on a new version, and one you threw
out stays thrown out.

A machine that ships is kept up to date file by file against the shipped copy, and
**nothing is ever deleted**. What ships is overwritten, because that is the machine;
anything else in the folder is yours, which is how a preset you saved onto a machine
survives the next version of it arriving.

## Machines and effects are two lists

A machine is played: notes go in and sound comes out, and in a song it becomes an
instrument with your name and your settings. An effect is not played: a whole track's
audio goes in and comes back changed, and in a song it is a box on a track's chain.

Registered and on the rack are the same fact for an effect, since there is nothing of
yours in one. A machine's box can be taken off the rack and put back, because the box
is an instrument you own.

## When one will not appear

A box whose id this build has no engine for is read and passed over rather than
refused, so a folder from a later version is harmless. That is also why a machine you
design under a new id never reaches the rack: the engine is in the application rather
than in the folder.
